# CubePod 0.8.0

## Features and improvements

- **Unified Workspace Block Volume Lifecycle ([CEP-0030](/ceps/0030-unified-workspace-block-volumes/), `#150`).** Extended `/volumes` with `type: "shared" | "block"` (default `"shared"`), mapping `"block"` volumes to `PodBoxSpec.VolumeMounts[].Type: "block"` and attaching ReadWriteOnce raw block `VolumeDevices` at `/workspace`. Added Kubernetes PVC attach-lease compare-and-swap (`cubepod.io/attached-sandbox`, `cubepod.io/attach-lease-expires`) with controller fencing (`WorkspaceVolumeLeaseLost`), independent CSI CoW workspace vs. RootFS forking, `PodWarmPool` block workspace preservation, and `cubepod volume migrate-legacy` (plus active `PodBox` auto-adoption and `volumes.allowLazyLegacyClaim`) gated by `featureGates.blockWorkspaceVolumes` (`CUBEPOD_FEATURE_BLOCK_WORKSPACE_VOLUMES`).
- **Firecracker NFSv3 Transport for Persistent Shared Volumes ([CEP-0031](/ceps/0031-firecracker-volume-nfs/), `#157`, `#158`).** Added `cubepod-volume-nfs` (`cmd/cubepod-volume-nfs`, `pkg/volumenfs`, Helm `volume-nfs.yaml`, and the new `ghcr.io/cubeplexai/cubepod-volume-nfs:v0.8.0` image), controller NFS lease pre-registration (`pkg/controller`), and in-guest `podd-init` `libc::mount(2)` NFSv3 mounting without requiring `nfs-common` or `mount.nfs`. Exempted ClusterIP NFS traffic in `pkg/egress` for kernel `rpciod` (`skuid 0`), enabled `featureGates.firecrackerVolumeNFS` by default, and added pinned experimental Firecracker NFSv3 guest kernel artifacts (`deploy/k8s/kata/guest-kernel/fc-nfs1.pin.json`, `test/guest-kernel/README.md`, opt-in `CEP0031_FC_NFS_GATE`).
- **Clean-Cut Volume Naming Unification (`#145`).** Normalized internal and deployment identifiers across CRDs (`PodBox.spec.volumeMounts`), Go (`K8sVolumeMounts`, `CUBEPOD_VOLUMES_*`, `cubepod_volume*`), Rust (`podd_init_volume_bind_duration_ms`), Helm (`volumes.*`, `featureGates.k8sVolumeMounts`, `volumes-pvc.yaml`), Prometheus alerts (`deploy/monitoring/volumes-alerts.yaml`), Docker Compose, and documentation from `e2bVolumes` to `volumes`.

## Fixes

- **PodTemplate `/status` Persistence & BuildKit Compatibility (`#146`, `#148`).** Fixed `PodTemplate` `/status` subresource updates and conflict refreshes during tag builds, added BuildKit cache PVC `storageClassName` wiring in Helm, and added compatibility with Kubernetes `<1.30` AppArmor annotations.
- **Volume HA, Docker Block Fork & Store Permissions.** Preserved HA `volumeMounts` fallback handling, fixed Docker block workspace CoW fork handling and fencing secret cleanup, and updated volume store directory permissions to `0710` so `cubepod-volume-nfs` can traverse tenant and volume directories.

## Known issues

- **Kata + Firecracker block device hotplug race (`#120`).** On Kata Containers with Firecracker (`kata-fc`), sandbox Pod creation can intermittently fail before any CubePod container starts with `EIO: I/O error` (`EXT4-fs (vdb): unable to read superblock`) due to a `virtio-mmio` drive hotplug race. Official SDK volume persistence tests on `kata-fc` remain skipped for `#120` in default CI runs unless `CEP0031_FC_NFS_GATE=1` is set; **Cloud Hypervisor (`kata-clh`) remains the recommended default Kata hypervisor** for production deployments. See [issue #120](https://github.com/cubeplexai/cubepod/issues/120).
- **Firecracker NFSv3 guest kernel prerequisite.** On `kata-fc`, persistent shared `/volumes` via `cubepod-volume-nfs` require a Kata guest kernel with built-in NFSv3 client support (stock Kata 4.4.0 bundles do not enable NFSv3; `deploy/k8s/kata/guest-kernel/fc-nfs1.pin.json` documents the experimental pinned kernel build).

## Before upgrading

Apply the updated CRDs (`PodBox.spec.volumeMounts[].type` and unified `volumeMounts` field schema) **before** running `helm upgrade`:

```bash
kubectl apply -f deploy/helm/cubepod/crds/
```

Review the following `0.8.0` breaking changes and migration steps before upgrading existing clusters:

- **Clean-cut Helm & environment variable rename (`e2bVolumes` -> `volumes`)**: Update `values.yaml` keys from `e2bVolumes.*` to `volumes.*`, `featureGates.k8sE2BVolumeMounts` to `featureGates.k8sVolumeMounts`, custom `CUBEPOD_E2B_VOLUMES_*` env vars to `CUBEPOD_VOLUMES_*`, and monitoring rules to `deploy/monitoring/volumes-alerts.yaml`. Note that KMS envelope / salted key derivations from pre-`0.8.0` `e2bVolumes` stores are not alias-compatible across this clean-cut rename.
- **Migrating pre-`0.8.0` `/workspace` data ([CEP-0030](/ceps/0030-unified-workspace-block-volumes/))**: Running `PodBox` sandboxes auto-adopt their existing workspace PVCs when updated, and offline legacy PVCs or local workspace directories can be previewed and migrated without copying data via `cubepod volume migrate-legacy --volumes-dir <dir> --dry-run` (or lazy-claimed on sandbox recreation with `volumes.allowLazyLegacyClaim: true`).
- **New `cubepod-volume-nfs` component & image alignment**: `volumes.nfs.enabled` deploys `cubepod-volume-nfs` behind `featureGates.firecrackerVolumeNFS: true`. Upgrade all 7 GHCR images (`cubepod-controller`, `cubepod-gateway`, `cubepod-egress`, `cubepod-podd`, `cubepod-volume-nfs`, `cubepod-sandbox-base`, `cubepod-desktop`), the `0.8.0` Helm Chart, and client SDKs (`pip install -U cubepod==0.8.0` / `npm install cubepod@0.8.0`) together.
