# CubePod 0.7.1

## Features and improvements

- **Complete GHCR image & manifest release + CI image build coverage.** Added `.github/workflows/ci.yml` (`sandbox-images-ci`) to build-verify `images/sandbox-base/Dockerfile` and `images/desktop/Dockerfile` on pull requests and pushes to `main`, and publishes the full 6-image GHCR release set (`cubepod-podd`, `cubepod-controller`, `cubepod-gateway`, `cubepod-egress`, `cubepod-sandbox-base`, `cubepod-desktop`) along with `release-manifest-v0.7.1.yaml`.

## Fixes

- **Fix `cubepod-desktop` image build (`images/desktop/Dockerfile`).** Added `libatomic1` (required by Playwright's bundled Node.js driver) and passed `--ignore-installed` to `pip install --no-cache-dir --break-system-packages` so installing `playwright` and Python data-science packages succeeds alongside Ubuntu 24.04 Debian-apt-managed packages.

## Known issues

- **Kata + Firecracker block device hotplug race (`#120`).** On Kata Containers with Firecracker (`kata-fc`), sandbox Pod creation can intermittently fail before any CubePod container starts with `EIO: I/O error` (`EXT4-fs (vdb): unable to read superblock`) due to a `virtio-mmio` drive hotplug race. See [issue #120](https://github.com/cubeplexai/cubepod/issues/120).
- **Firecracker + E2B volume mount persistence (`#122`).** Kata Firecracker lacks `virtio-fs` filesystem sharing, so official E2B `volumeMounts` (currently staged as filesystem directories via `ShareFile` host-to-guest copy) do not write guest changes back to the volume across sandbox recreation on `kata-fc`. See [issue #122](https://github.com/cubeplexai/cubepod/issues/122).
- **Recommended default hypervisor: Cloud Hypervisor (`kata-clh`).** For Kubernetes Kata MicroVM deployments, **Cloud Hypervisor (`kata-clh`) is recommended as the default hypervisor** until `#120` and `#122` are resolved. In CI, the `kata-clh` lane passes the full official Python and TypeScript E2B SDK suites with zero skipped tests.

## Before upgrading

If upgrading from `0.6.0` or earlier, apply the updated `SandboxWebhook` CRD (`status.deadLetters`) **before** running `helm upgrade`:

```bash
kubectl apply -f deploy/helm/cubepod/crds/
```

If upgrading from `0.6.0` or earlier, also review the `0.7.x` changes in [0.7.0](/changelog/0.7.0/) and [Kubernetes & Helm Deployment](/deployment/kubernetes-helm/) (`gateway.panelSecret` / `CUBEPOD_PANEL_SECRET` required at startup, `featureGates.e2bTemplateAPI` defaulting to `true`, and `runtime.runtimeClassName: "kata-clh"` recommended for Kata).

Upgrade `cubepod-controller`, `cubepod-gateway`, `cubepod-egress`, `cubepod-podd`, `cubepod-sandbox-base`, and `cubepod-desktop` images together with the `0.7.1` Helm Chart, and update client SDKs (`pip install -U cubepod==0.7.1` / `npm install cubepod@0.7.1`).
