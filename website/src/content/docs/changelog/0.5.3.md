# CubePod 0.5.3

## Fixes

- **WarmPool readiness probe & sub-second claim fast path (`#84`).** Attached a `podd` `/health` (`:49983`) `readinessProbe` to sandbox Pods in `BuildKataPod`, updated `RESTKubeClient` to wait for `Ready=True` and surface `PodIP`/`NotReady` in `ListPods`, and updated `Reconcile` so `WarmPoolClaimed` reuses the standby `PodIP` directly instead of issuing a redundant `EnsurePod` (`409 Conflict`) round-trip.
- **Python SDK case-insensitive terminal states (`#83`).** Treated sandbox terminal states case-insensitively in the Python SDK so lowercase E2B wire states (`running`, `paused`, `terminated`, `failed`) match cleanly.

## Before upgrading

No CRD schema changes are introduced in `0.5.3` compared to `0.5.2` (if upgrading from `v0.5.0` or earlier, apply `kubectl apply -f deploy/helm/cubepod/crds/` first).

Upgrade `cubepod-controller`, `cubepod-gateway`, `cubepod-egress`, and `cubepod-podd` images together with the `0.5.3` Helm Chart via the [Kubernetes & Helm deployment guide](/deployment/kubernetes-helm/), and update client SDKs (`pip install -U cubepod==0.5.3` / `npm install cubepod@0.5.3`).
