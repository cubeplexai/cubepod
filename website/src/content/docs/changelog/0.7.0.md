# CubePod 0.7.0

## Features and improvements

- **E2B Template API GA, S3 Context Store & BuildKit mTLS/HA (`#114`).** Promoted `E2BTemplateAPI` (`featureGates.e2bTemplateAPI`) to default `true`, added an S3 template build context store (`templateBuild.contextStore.backend: "s3"`) so `cubepod-controller` can run multi-replica HA with `templateBuild.enabled: true`, and added BuildKit `StatefulSet` HA + mTLS support (`templateBuild.buildkit.tls`). See [Kubernetes & Helm Deployment](/deployment/kubernetes-helm/) and [Templates Guide](/sdks/templates/).
- **HTTP/2 (`h2`) ALPN Negotiation in Zero-Trust Egress ([CEP-0020](/ceps/0020-transparent-zero-trust-egress/), `#107`).** Added `h2` + `http/1.1` ALPN negotiation on `cubepod-egress`'s selective HTTPS MITM listener, preserving `:authority`/SNI validation (`421`), header transforms, `cpodref_` exchange (`403` on unauthorized targets), streaming flushes, and `cubepod_egress_mitm_alpn_total` metrics.
- **Kubernetes-Native Sandbox Events & Webhooks HA (`#115`).** Wired `events.backend: "k8s"` across Helm, Gateway, and Controller using `SandboxWebhook` CRs with `status.deadLetters` (up to 50 entries), companion `Secret` storage for HMAC signing keys, `PodBox` `core/v1` `Event`s, and `deploy/monitoring/webhook-alerts.yaml`.
- **Desktop Neko WebRTC Packaging, `browser_tab_follow` & Unified GHCR Images (`#116`, `#138`).** Packaged Neko WebRTC and GStreamer runtime plugins directly in `images/desktop`, implemented `browser_tab_follow` (`/opt/cubepod/desktop/browser_tab_follow.py` and Python SDK helpers), unified `images/sandbox-base`, de-branded `images/desktop` UID/GID `1000` user handling, and added `cubepod-sandbox-base` and `cubepod-desktop` to the GHCR release matrix.
- **Volume KMS Envelope Encryption, Key Rotation & RWX Alerts (`#112`).** Added KMS envelope encryption and API-key rotation support for E2B volumes along with `deploy/monitoring/e2b-volumes-alerts.yaml`.
- **Expanded Observability & Periodic Metrics Sampler (`#108`, `#109`).** Added a background sandbox metrics sampler (`gateway.metricsSampleInterval: "10s"`), dedicated filesystem watch/stream and secret-store latency Prometheus histograms, Grafana dashboard (`deploy/monitoring/sandbox-metrics-dashboard.json`), and `PrometheusRule` alerts (`deploy/monitoring/sandbox-metrics-rules.yaml`, `watcher-secret-alerts.yaml`).
- **Longhorn V2 Security Review, Kata Block Verification & Soak Suite (`#113`).** Documented the Longhorn V2 privileged DaemonSet security review in [Kata & Block Storage](/deployment/kata-and-block-storage/), added `deploy/k8s/longhorn-v2/volumesnapshotclass.yaml`, non-disruptive in-guest Kata `virtio-blk` verification (`TestK8sKataVirtioBlkGuestVerification`), and multi-hour concurrent soak tests (`make test-soak`).
- **Reproducible `kind`, `Compose` & `Kata` Dual-SDK E2E Pipelines (`#111`, `#117`, `#118`, `#140`, `#141`).** Added isolated `kind`, Docker Compose, and KVM Kata (`kata-clh` and `kata-fc`) E2E suites running the official Python and TypeScript E2B SDKs, plus bilingual `README` updates. See [Reproducible kind E2E](/deployment/kind-e2e/) and [Docker Compose](/deployment/docker-compose/).

## Fixes

- **Controller & Gateway Lifecycle State-Machine Hardening (`#124`, `#129`, `#133`, `#134`, `#135`, `#137`, `#139`).** Prevented `Terminated` `PodBox` instances from being resurrected, synced `Failed` phases to the reconciler and cleared stale leases, rejected lease/timeout/refresh operations on terminated sandboxes, enforced `PodIP` readiness before claiming `PodWarmPool` standbys or retiring templates, reconciled provisioning `PodBox`es when Pods become ready, deep-copied templates returned by `GetPodTemplate`, and standardized E2B JSON error payloads on sandbox API failures.
- **Panel HMAC Secret & Target URL Security (`#126`, `#128`).** Required a valid `CUBEPOD_PANEL_SECRET` at `cubepod-gateway` startup (auto-generated and reused via `panel-secret.yaml` in Helm or persisted by `gateway-entrypoint.sh` in Compose) and ignored client-supplied `targetUrl` values when minting panel tokens.
- **Metrics, E2B Volume Mount & Docker Runtime Fixes (`#109`, `#111`).** Stopped the metrics sampler from resurrecting deleted series, gated gauges to running sandboxes, mounted E2B volumes without container `CAP_SYS_ADMIN` in no-pivot mode, and wired isolated Docker filesystem sandboxes.

## Known issues

- **Kata + Firecracker block device hotplug race (`#120`).** On Kata Containers with Firecracker (`kata-fc`), sandbox Pod creation can intermittently fail before any CubePod container starts with `EIO: I/O error` (`EXT4-fs (vdb): unable to read superblock`) due to a `virtio-mmio` drive hotplug race. See [issue #120](https://github.com/cubeplexai/cubepod/issues/120).
- **Firecracker + E2B volume mount persistence (`#122`).** Kata Firecracker lacks `virtio-fs` filesystem sharing, so official E2B `volumeMounts` (currently staged as filesystem directories via `ShareFile` host-to-guest copy) do not write guest changes back to the volume across sandbox recreation on `kata-fc`. See [issue #122](https://github.com/cubeplexai/cubepod/issues/122).
- **Recommended default hypervisor: Cloud Hypervisor (`kata-clh`).** For Kubernetes Kata MicroVM deployments, **Cloud Hypervisor (`kata-clh`) is recommended as the default hypervisor** until `#120` and `#122` are resolved. In CI, the `kata-clh` lane passes the full official Python and TypeScript E2B SDK suites with zero skipped tests.

## Before upgrading

`0.7.0` updates the `SandboxWebhook` CRD schema (`status.deadLetters`). Apply the latest CRDs **before** running `helm upgrade`:

```bash
kubectl apply -f deploy/helm/cubepod/crds/
```

Review the following `0.7.0` behavioral changes in [Kubernetes & Helm Deployment](/deployment/kubernetes-helm/):
- **Panel HMAC secret required (`gateway.panelSecret` / `CUBEPOD_PANEL_SECRET`)**: `cubepod-gateway` now refuses to start with an empty or placeholder secret. Online Helm installs/upgrades generate and reuse `<fullname>-panel-secret` automatically when `gateway.panelSecret` is empty; GitOps / `helm template` deployments should set `gateway.existingPanelSecret`.
- **`featureGates.e2bTemplateAPI` defaults to `true`**: `GET /templates` now returns the E2B `E2BTemplate[]` array by default. Set `featureGates.e2bTemplateAPI: false` to roll back to the legacy `{"templates":[...]}` wrapper.
- **Recommended Kata `RuntimeClass`**: If choosing between Firecracker and Cloud Hypervisor for Kata workloads, configure `runtime.runtimeClassName: "kata-clh"`.

Upgrade `cubepod-controller`, `cubepod-gateway`, `cubepod-egress`, and `cubepod-podd` images (and `cubepod-sandbox-base` / `cubepod-desktop` if used) together with the `0.7.0` Helm Chart, and update client SDKs (`pip install -U cubepod==0.7.0` / `npm install cubepod@0.7.0`).
