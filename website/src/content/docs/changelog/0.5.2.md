# CubePod 0.5.2

## Features and improvements

- **Complete Helm Chart configuration wiring (`#80`).** Wired `runtime.*`, `storage.*`, `egress.*`, `global.imagePullSecrets`, `runtime.templatePullSecret`, `gateway.livePodRouting`, and `gateway.persistence` / `stateDir` into [the Helm Chart](/deployment/kubernetes-helm/), added `gateway-state-pvc.yaml`, and added `egress.caSecretName` / `egress.upstreamCAEnabled` secret mounting across both controller and gateway Deployments.
- **Default egress sidecar image flag & Gateway pull secrets (`#80`).** Added `--egress-image` (`CUBEPOD_EGRESS_IMAGE`) and `controller.WithDefaultEgressImage` to `cubepod-controller` and `cubepod-gateway`, and wired `--image-pull-secrets` (`CUBEPOD_IMAGE_PULL_SECRETS`) on `cubepod-gateway`.
- **Local Kubernetes maintenance template & CRD reference sync (`#80`).** Added `deploy/k8s/local.example/` as a reproducible Helm-based cluster maintenance template alongside a gitignored `deploy/k8s/local/` workspace, and included `SandboxWebhook` (`cubepod.io_sandboxwebhooks.yaml`) in generated CRD documentation.

## Fixes

- **Helm `SandboxWebhook` RBAC & Gateway `CUBEPOD_STATE` events directory (`#80`).** Added `sandboxwebhooks` and `sandboxwebhooks/status` permissions to `deploy/helm/cubepod/templates/rbac.yaml`, and fixed `cubepod-gateway` to derive `eventsDir` from `effectiveStateDir` (`CUBEPOD_STATE` or `--state-dir`).

## Before upgrading

If upgrading from `v0.5.0` or earlier, apply the latest CRDs before running `helm upgrade`:

```bash
kubectl apply -f deploy/helm/cubepod/crds/
```

Upgrade `cubepod-controller`, `cubepod-gateway`, `cubepod-egress`, and `cubepod-podd` images together with the `0.5.2` Helm Chart via the [Kubernetes & Helm deployment guide](/deployment/kubernetes-helm/), and update client SDKs (`pip install -U cubepod==0.5.2` / `npm install cubepod@0.5.2`).
