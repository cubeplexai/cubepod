# CubePod 0.5.4

## Fixes

- **Non-blocking Gateway health probes during slow sandbox reconciliation (`#86`).** Introduced per-sandbox operation serialization (`lockSandboxOp`) in `pkg/gateway` and refactored `handlePauseSandbox`, `handleConnectSandbox`, `handleResetRootfs`, and `ensureRunning` to release `Server.mu` across blocking Kubernetes `Reconcile`, `waitForPoddReady`, and runtime lifecycle calls. Prevents kubelet `GET /health` liveness probes from timing out while waiting on `Server.mu.RLock()` during long-running Longhorn/Kata PodBox startup or RootFS reset operations.

## Before upgrading

No CRD schema changes are introduced in `0.5.4` compared to `0.5.3` (if upgrading from `v0.5.0` or earlier, apply `kubectl apply -f deploy/helm/cubepod/crds/` first).

Upgrade `cubepod-controller`, `cubepod-gateway`, `cubepod-egress`, and `cubepod-podd` images together with the `0.5.4` Helm Chart via the [Kubernetes & Helm deployment guide](/deployment/kubernetes-helm/), and update client SDKs (`pip install -U cubepod==0.5.4` / `npm install cubepod@0.5.4`).
