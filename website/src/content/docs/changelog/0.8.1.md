# CubePod 0.8.1

## Features and improvements

- **Lower cold-start and resume latency (`#164`, `#166`, `#169`).**
  - `podd-init` formats new ext4 volumes with lazy inode-table/journal initialization and no discard. On wake it mounts existing volumes directly and only falls back to `e2fsck -p` when the mount fails. It also replaces `mount` subprocesses with direct `mount(2)` syscalls.
  - The controller and gateway use Kubernetes Pod watches instead of fixed 500 ms polling, and set `ReadinessProbe.initialDelaySeconds: 0` and `IfNotPresent` pulls for the `egress` sidecar. `PodBox` upserts take a fast path when the resource version is known.
  - The global reconciler lock is replaced with per-box and per-pool locks, so Kubernetes and NFS I/O is no longer serialized across sandboxes. PVC, egress Secret, VolumeSnapshot, and WarmPool replica operations run in parallel.
  - Valid egress mTLS Secrets are kept across pause and resume, and WarmPools replenish right after a claim.
  - With `--live-pod-routing`, the gateway probes `http://<podIP>:49983/health` directly once the Pod is `Running`. This skips the kubelet readiness round-trip. WarmPool standby Pods are excluded.
- **Optional hostPath `podd` injection (`#169`).** Set `runtime.poddInjectionMode: hostPath` to deploy the `cubepod-podd-agent` DaemonSet. It stages `podd-init` and `podd` into `runtime.poddHostPath` (default `/var/lib/cubepod/bin/active`) on each node, and sandbox Pods mount that directory read-only at `/opt/cubepod/bin` instead of running the `podd-installer` initContainer. The default stays `initContainer`. `PodTemplate`s that override `poddImage` fall back to the initContainer automatically. See [Kubernetes (Helm)](/deployment/kubernetes-helm/).
- **Per-phase latency metrics (`#166`).** New histograms: `cubepod_sandbox_cold_start_phase_duration_seconds` and `cubepod_sandbox_resume_phase_duration_seconds` on the gateway, and `cubepod_reconcile_phase_duration_seconds` on the controller. They're available in both Prometheus text and JSON `/metrics`. See [API Overview](/reference/api-overview/).
- **Named volume mounts in the Go SDK, CLI, and MCP server (`#170`, `#172`).**
  - Go SDK: `CreateSandboxRequest.VolumeMounts` (`[]client.SandboxVolumeMount{Name, Path}`).
  - CLI: `cubepod sandbox create --volume-mount NAME:PATH` (repeatable).
  - MCP: `volumeMounts` and `volumeKey` arguments on `cubepod_create_sandbox`.
  - Named mounts need an API key. The CLI and MCP server fail fast with an actionable error when none is configured. See [Go SDK & CLI](/sdks/go-and-cli/) and [MCP Server](/sdks/mcp-server/).
- **Go SDK sends `X-API-KEY` (`#170`).** `client.WithAPIKey` now sends `X-API-KEY` in addition to `Authorization: Bearer`, matching the Python and TypeScript SDKs.

## Fixes

- **Whitespace in volume mount paths (`#173`).** The gateway trims leading and trailing whitespace from `volumeMounts[].path` on `POST /sandboxes`. Before, `"/data "` passed validation and silently mounted at a directory literally named `data `, and padded duplicate paths weren't detected. The CLI and MCP server trim names and paths the same way.

## Before upgrading

- **No CRD changes.** No `kubectl apply -f deploy/helm/cubepod/crds/` is needed before `helm upgrade` from 0.8.0.
- **Upgrade the control plane and the `cubepod-podd` image together.** The `podd-init` mount changes ship in `ghcr.io/cubeplexai/cubepod-podd:v0.8.1`. The chart's `runtime.poddInjectorImage` default already points to it.
- **hostPath injection is opt-in.** Switching `runtime.poddInjectionMode` to `hostPath` deploys a DaemonSet that writes to `runtime.poddHostPath` on every node. Make sure your Pod Security admission policy allows `hostPath` volumes in the CubePod namespace.
- **Go SDK and CLI clients now send `X-API-KEY`.** Sandboxes created by Go clients with an API key are recorded as owned by that key's tenant. When `BlockWorkspaceVolumes` and lazy legacy volume claims are enabled, the gateway may adopt a legacy `volumeKey` workspace as a block `/workspace` volume, and it returns `403` if that volume belongs to another tenant.
