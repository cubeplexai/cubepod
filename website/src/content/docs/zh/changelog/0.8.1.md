# CubePod 0.8.1

## 功能与改进

- **降低冷启动与恢复延迟（`#164`、`#166`、`#169`）。**
  - `podd-init` 格式化新的 ext4 卷时延迟初始化 inode 表与日志，且不执行 discard。唤醒时直接挂载已有卷，仅在挂载失败时回退到 `e2fsck -p`。同时用直接的 `mount(2)` 系统调用替代 `mount` 子进程。
  - 控制器与网关改用 Kubernetes Pod Watch 代替固定 500 ms 轮询，并将 `ReadinessProbe.initialDelaySeconds` 设为 `0`、`egress` 边车拉取策略设为 `IfNotPresent`。已知资源版本时，`PodBox` 写入走快速路径。
  - 全局调谐锁拆分为按沙箱、按池加锁，不同沙箱之间的 Kubernetes 与 NFS I/O 不再串行。PVC、egress Secret、VolumeSnapshot 与 WarmPool 副本操作并行执行。
  - 暂停/恢复期间复用仍然有效的 egress mTLS Secret，WarmPool 在被认领后立即补充。
  - 开启 `--live-pod-routing` 时，Pod 进入 `Running` 后网关直接探测 `http://<podIP>:49983/health`，省去 kubelet 就绪探针那一轮往返。WarmPool 待命 Pod 不走这条路径。
- **可选的 hostPath `podd` 注入（`#169`）。** 设置 `runtime.poddInjectionMode: hostPath` 后会部署 `cubepod-podd-agent` DaemonSet，在每个节点上把 `podd-init` 与 `podd` 放到 `runtime.poddHostPath`（默认 `/var/lib/cubepod/bin/active`）。沙箱 Pod 以只读方式把该目录挂载到 `/opt/cubepod/bin`，不再运行 `podd-installer` initContainer。默认仍为 `initContainer`。自定义了 `poddImage` 的 `PodTemplate` 会自动回退到 initContainer。详见 [Kubernetes（Helm）](/zh/deployment/kubernetes-helm/)。
- **分阶段延迟指标（`#166`）。** 新增直方图：网关侧的 `cubepod_sandbox_cold_start_phase_duration_seconds` 与 `cubepod_sandbox_resume_phase_duration_seconds`，控制器侧的 `cubepod_reconcile_phase_duration_seconds`，Prometheus 文本格式与 JSON `/metrics` 均可获取。详见 [API 概览](/zh/reference/api-overview/)。
- **Go SDK、CLI 与 MCP 服务端支持命名卷挂载（`#170`、`#172`）。**
  - Go SDK：`CreateSandboxRequest.VolumeMounts`（`[]client.SandboxVolumeMount{Name, Path}`）。
  - CLI：`cubepod sandbox create --volume-mount NAME:PATH`（可重复使用）。
  - MCP：`cubepod_create_sandbox` 新增 `volumeMounts` 与 `volumeKey` 参数。
  - 命名卷挂载需要 API key。未配置时，CLI 与 MCP 服务端会直接报错并提示如何配置。详见 [Go SDK 与 CLI](/zh/sdks/go-and-cli/) 与 [MCP 服务端](/zh/sdks/mcp-server/)。
- **Go SDK 发送 `X-API-KEY`（`#170`）。** `client.WithAPIKey` 除 `Authorization: Bearer` 外还会发送 `X-API-KEY`，与 Python、TypeScript SDK 保持一致。

## 问题修复

- **卷挂载路径中的首尾空白（`#173`）。** 网关现在会去除 `POST /sandboxes` 中 `volumeMounts[].path` 的首尾空白。此前 `"/data "` 能通过校验，并被静默挂载到名为 `data ` 的目录；仅首尾空白不同的重复路径也无法识别。CLI 与 MCP 服务端对卷名和路径做同样处理。

## 升级前注意事项

- **无 CRD 变更。** 从 0.8.0 升级时，`helm upgrade` 前无需执行 `kubectl apply -f deploy/helm/cubepod/crds/`。
- **控制面与 `cubepod-podd` 镜像需同步升级。** `podd-init` 的挂载优化包含在 `ghcr.io/cubeplexai/cubepod-podd:v0.8.1` 中，Chart 中 `runtime.poddInjectorImage` 的默认值已指向该镜像。
- **hostPath 注入需手动开启。** 将 `runtime.poddInjectionMode` 设为 `hostPath` 后，会部署一个向每个节点的 `runtime.poddHostPath` 写入文件的 DaemonSet。请确认 CubePod 所在命名空间的 Pod Security 准入策略允许使用 `hostPath` 卷。
- **Go SDK 与 CLI 客户端现在会发送 `X-API-KEY`。** 带 API key 的 Go 客户端创建的沙箱会被记录为归属该 key 对应的租户。开启 `BlockWorkspaceVolumes` 与旧卷懒接管时，网关可能把旧版 `volumeKey` 工作区接管为 `/workspace` 块卷；若该卷属于其他租户，则返回 `403`。
