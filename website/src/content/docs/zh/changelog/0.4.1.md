# CubePod 0.4.1

## 功能与改进

- **基于 `volumeKey` 的确定性工作区持久化。** 创建沙箱时可传入 `volumeKey`，绑定确定性的 `/workspace` PVC（`PodBox.spec.volumeKey`），在沙箱删除并重建后保留工作区数据；已同步支持 Gateway API、Kubernetes Controller、[Python SDK](/zh/sdks/python/) 与 [TypeScript SDK](/zh/sdks/typescript/)。
- **有序出站策略规则（`networkPolicy.egress`）。** 支持在 `PodBox` 与 `POST /sandboxes` 中配置按顺序求值的 `allow` / `deny` 域名及通配符规则，并在 Gateway、Controller 与[零信任出站代理](/zh/concepts/zero-trust-egress/)中统一执行。
- **空请求体 `archive-sync`。** `podd`、Gateway 与 Python SDK 的 `POST /files/archive-sync` 支持空请求体，允许仅通过 `remove_paths` 清理目标路径而无需上传 tar 归档。
- **中英文文档站与交互式 OpenAPI 控制台。** 新增部署于 `cubepod.cubeplex.ai` 的双语 Astro + Starlight 文档站，提供交互式 [OpenAPI 控制台](/zh/api/)、自动同步的 [CRD](/zh/reference/crds/) 与 [Helm 参数参考](/zh/reference/helm-values/)，以及 `llms.txt` / `llms-full.txt` 索引。

## 问题修复

- **CRD 字段补全与策略动作归一化。** 为 `PodBox` CRD 补齐 `volumeKey` 与 `networkPolicy.egress` Schema，并在 Gateway 与出站策略求值器中对规则动作大小写进行归一化处理。

## 升级前注意事项

本次更新在 `PodBox` CRD 中新增了 `spec.volumeKey` 与 `spec.networkPolicy.egress`。由于 Helm 在 `helm upgrade` 时不会自动更新 `crds/` 目录，请务必先显式应用最新 CRD 清单：

```bash
kubectl apply -f deploy/helm/cubepod/crds/
```

随后按 [Kubernetes 与 Helm 部署指南](/zh/deployment/kubernetes-helm/) 将 `cubepod-controller`、`cubepod-gateway`、`cubepod-egress` 与 `cubepod-podd` 同步升级至 `v0.4.1`，并升级客户端 SDK（`pip install -U cubepod` / `npm install cubepod@0.4.1`）。
