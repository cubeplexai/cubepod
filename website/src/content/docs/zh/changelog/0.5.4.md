# CubePod 0.5.4

## 问题修复

- **避免慢速沙箱 Reconcile 阻塞 Gateway 健康探针（`#86`）。** 在 `pkg/gateway` 中引入按沙箱粒度的操作串行锁（`lockSandboxOp`），并重构 `handlePauseSandbox`、`handleConnectSandbox`、`handleResetRootfs` 与 `ensureRunning`，使其在耗时的 Kubernetes `Reconcile`、`waitForPoddReady` 及运行时生命周期 I/O 期间释放 `Server.mu` 全局锁，避免 kubelet `GET /health` 存活探针在 Longhorn/Kata PodBox 启动或 RootFS 重置期间因等待 `Server.mu.RLock()` 而超时触发容器重启。

## 升级前注意事项

`0.5.4` 相比 `0.5.3` 无 CRD 变更（如从 `v0.5.0` 或更早版本升级，请先执行 `kubectl apply -f deploy/helm/cubepod/crds/`）。

请按 [Kubernetes 与 Helm 部署指南](/zh/deployment/kubernetes-helm/) 将 `cubepod-controller`、`cubepod-gateway`、`cubepod-egress` 与 `cubepod-podd` 镜像及 Helm Chart 同步升级至 `v0.5.4`，并更新客户端 SDK（`pip install -U cubepod==0.5.4` / `npm install cubepod@0.5.4`）。
