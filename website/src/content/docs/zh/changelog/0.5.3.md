# CubePod 0.5.3

## 问题修复

- **WarmPool 就绪探测与毫秒级 claim 快速路径（`#84`）。** 在 `BuildKataPod` 主容器中挂载 `podd` `/health`（`:49983`）`readinessProbe`，让 `RESTKubeClient` 等待 `Ready=True` 并在 `ListPods` 中透传 `PodIP`/`NotReady` 状态，同时让 `Reconcile` 在 `WarmPoolClaimed` 路径上直接复用备用 Pod 的 `PodIP` 并跳过多余的 `EnsurePod`（`409 Conflict`）往返。
- **Python SDK 终态大小写兼容（`#83`）。** Python SDK 对沙箱终态检查改为大小写不敏感，以兼容 E2B 小写状态值。

## 升级前注意事项

`0.5.3` 相比 `0.5.2` 无 CRD 变更（如从 `v0.5.0` 或更早版本升级，请先执行 `kubectl apply -f deploy/helm/cubepod/crds/`）。

请按 [Kubernetes 与 Helm 部署指南](/zh/deployment/kubernetes-helm/) 将 `cubepod-controller`、`cubepod-gateway`、`cubepod-egress` 与 `cubepod-podd` 镜像及 Helm Chart 同步升级至 `v0.5.3`，并更新客户端 SDK（`pip install -U cubepod==0.5.3` / `npm install cubepod@0.5.3`）。
