# CubePod 0.7.0

## 功能与改进

- **E2B 模板 API 转正（GA）、S3 上下文存储与 BuildKit mTLS/HA（`#114`）。** 将 `featureGates.e2bTemplateAPI` 默认值调整为 `true`；新增 S3 构建上下文存储后端（`templateBuild.contextStore.backend: "s3"`），使 `cubepod-controller` 在启用 `templateBuild.enabled: true` 时也可多副本 HA 运行；同时新增 BuildKit `StatefulSet` 多副本与 mTLS 支持（`templateBuild.buildkit.tls`）。请参阅[Kubernetes 与 Helm 部署](/zh/deployment/kubernetes-helm/)与[模板指南](/zh/sdks/templates/)。
- **零信任出站选择性 MITM 支持 HTTP/2（`h2`）ALPN 协商（[CEP-0020](/ceps/0020-transparent-zero-trust-egress/)，`#107`）。** `cubepod-egress` 客户端侧 TLS 监听器现同时通告 `h2` 与 `http/1.1`，在保留 `:authority`/SNI 一致性校验（`421`）、请求头改写、`cpodref_` 置换校验（越权返回 `403`）及流式即时刷新的基础上支持 HTTP/2 多路复用，并导出 `cubepod_egress_mitm_alpn_total` 指标。
- **Kubernetes 原生沙箱事件与 Webhook HA（`#115`）。** 在 Helm、Gateway 与 Controller 之间全面接通 `events.backend: "k8s"`：Webhook 持久化为 `SandboxWebhook` CR（含最多 50 条 `status.deadLetters` 死信队列），HMAC 签名密钥独立存放在配套 `Secret` 中，生命周期事件写入 `PodBox` 的 `core/v1` `Event`，并提供 `deploy/monitoring/webhook-alerts.yaml` 告警规则。
- **桌面镜像内置 Neko WebRTC、`browser_tab_follow` 与统一 GHCR 镜像发布（`#116`、`#138`）。** 在 `images/desktop` 中开箱预装 Neko WebRTC 及 GStreamer 运行时插件，实现 `browser_tab_follow`（`/opt/cubepod/desktop/browser_tab_follow.py` 及 Python SDK 辅助接口），统一 `images/sandbox-base`，完成 `images/desktop` UID/GID `1000` 用户去品牌化，并将 `cubepod-sandbox-base` 与 `cubepod-desktop` 纳入 GHCR 正式发布流水线。
- **E2B 卷 KMS 信封加密、API-Key 轮换与 RWX 容量告警（`#112`）。** 为 E2B 持久化卷新增 KMS 信封加密与密钥轮换能力，并补充 `deploy/monitoring/e2b-volumes-alerts.yaml`。
- **可观测性增强与周期性沙箱指标采样器（`#108`、`#109`）。** 新增后台沙箱指标采样器（`gateway.metricsSampleInterval: "10s"`）、独立的 Watch/流式与 Secret Store 延迟直方图指标、Grafana 仪表盘（`deploy/monitoring/sandbox-metrics-dashboard.json`）及 Prometheus 告警规则（`sandbox-metrics-rules.yaml`、`watcher-secret-alerts.yaml`）。
- **Longhorn V2 安全评审、Kata 裸块验证与长稳压测套件（`#113`）。** 在[Kata Containers 与块存储配置](/zh/deployment/kata-and-block-storage/)记录 Longhorn V2 特权 DaemonSet 安全评估，新增 `deploy/k8s/longhorn-v2/volumesnapshotclass.yaml`、无侵入 Guest 内 Kata `virtio-blk` 验证（`TestK8sKataVirtioBlkGuestVerification`）以及多小时并发压测套件（`make test-soak`）。
- **可复现的 `kind`、`Compose` 与 `Kata` 双官方 SDK E2E 流水线（`#111`、`#117`、`#118`、`#140`、`#141`）。** 新增基于官方 Python 与 TypeScript E2B SDK 的隔离式 `kind`、Docker Compose 与 KVM Kata（`kata-clh` / `kata-fc`）E2E 测试流水线，并补充中英文 README 与部署文档。请参阅 [Docker Compose 部署](/zh/deployment/docker-compose/)。

## 问题修复

- **Controller 与 Gateway 生命周期状态机加固（`#124`、`#129`、`#133`、`#134`、`#135`、`#137`、`#139`）。** 防止已进入 `Terminated` 终态的 `PodBox` 被错误复活；将 `Failed` 阶段同步至调谐器并清理残留租约；拒绝在已终止沙箱上执行租约/超时/续期操作；在认领 `PodWarmPool` 预热副本或淘汰旧模板前强制校验 `PodIP` 就绪；修复 Pod 就绪后 `Provisioning` 状态 `PodBox` 调谐；对 `GetPodTemplate` 返回值做深拷贝；并统一沙箱接口失败时的 E2B JSON 错误响应格式。
- **Panel HMAC 密钥与目标 URL 安全加固（`#126`、`#128`）。** 要求 `cubepod-gateway` 启动时必须提供有效的 `CUBEPOD_PANEL_SECRET`（Helm 在线安装/升级自动生成并复用 `panel-secret.yaml`，Compose 由 `gateway-entrypoint.sh` 自动持久化），并在签发 Panel Token 时忽略客户端传入的 `targetUrl`。
- **指标采样、E2B 卷挂载与 Docker 运行时修复（`#109`、`#111`）。** 修复指标采样器复活已删除沙箱序列的问题并将 Gauge 限定为运行中沙箱；支持无 `CAP_SYS_ADMIN` 特权的非 pivot 模式 E2B 卷挂载；完善隔离式 Docker 文件系统沙箱链路。

## 已知问题

- **Kata + Firecracker 块设备热插拔竞态问题（`#120`）。** 在 Kata Containers 搭配 Firecracker（`kata-fc`）运行时，沙箱 Pod 在业务容器启动前偶发因 `virtio-mmio` 块设备热插拔竞态导致 `EIO: I/O error`（`EXT4-fs (vdb): unable to read superblock`）并超时失败。详见 [issue #120](https://github.com/cubeplexai/cubepod/issues/120)。
- **Firecracker + E2B Volume 挂载持久化限制（`#122`）。** 由于 Kata Firecracker 不支持 `virtio-fs` 文件系统共享，目前基于宿主机目录拷贝（`ShareFile`）暂存的官方 E2B `volumeMounts` 在 `kata-fc` 上无法将 Guest 内的写入同步写回宿主机，沙箱销毁重建后数据不会保留。详见 [issue #122](https://github.com/cubeplexai/cubepod/issues/122)。
- **推荐默认使用 Cloud Hypervisor（`kata-clh`）。** 在 `#120` 与 `#122` 修复前，生产 Kubernetes Kata MicroVM 部署**推荐默认使用 Cloud Hypervisor（`kata-clh`）**。在 CI 中，`kata-clh` 流水线已完整通过官方 Python 与 TypeScript E2B SDK 全部测试场景且零跳过。

## 升级前注意事项

`0.7.0` 更新了 `SandboxWebhook` CRD Schema（新增 `status.deadLetters` 字段）。执行 `helm upgrade` **之前**请务必先应用最新 CRD 清单：

```bash
kubectl apply -f deploy/helm/cubepod/crds/
```

升级前请核对 [Kubernetes 与 Helm 部署指南](/zh/deployment/kubernetes-helm/) 中的 `0.7.0` 行为变更：
- **强制要求配置 Panel HMAC 密钥（`gateway.panelSecret` / `CUBEPOD_PANEL_SECRET`）**：`cubepod-gateway` 现在会在密钥为空或仍为示例占位符时拒绝启动。在线使用 Helm 安装/升级且 `gateway.panelSecret` 留空时会自动生成并复用 `<fullname>-panel-secret`；GitOps 或离线 `helm template` 场景请配置 `gateway.existingPanelSecret`。
- **`featureGates.e2bTemplateAPI` 默认开启（`true`）**：`GET /templates` 默认返回符合 E2B 规范的 `E2BTemplate[]` 数组；如需回退旧版 `{"templates":[...]}` 包装结构，请显式设置 `featureGates.e2bTemplateAPI: false`。
- **推荐 Kata `RuntimeClass`**：在 Firecracker 与 Cloud Hypervisor 之间选择时，推荐将 `runtime.runtimeClassName` 配置为 `"kata-clh"`。

请将 `cubepod-controller`、`cubepod-gateway`、`cubepod-egress`、`cubepod-podd` 镜像（以及如使用的 `cubepod-sandbox-base` / `cubepod-desktop`）与 `0.7.0` Helm Chart 同步升级，并更新客户端 SDK（`pip install -U cubepod==0.7.0` / `npm install cubepod@0.7.0`）。
