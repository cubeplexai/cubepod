# CubePod 0.6.0

## 功能与改进

- **E2B 沙箱监控指标与全栈 Prometheus 可观测性（[CEP-0029](/ceps/0029-e2b-sandbox-metrics/)，`#92`）。** 新增兼容 E2B 的 `GET /sandboxes/{id}/metrics` 与 `GET /sandboxes/metrics` 接口，底层由 Guest 内 `podd` 实时采样提供（`GET /metrics` 与 `GET /v1/prometheus`，并读取 `/run/cubepod/init-state.json` 上报 `podd-init` 启动耗时）。同时在 Gateway（`:8080/metrics`）、Controller（`:8081/metrics`）与 Egress（`:19090/metrics`）补全 E2B 请求延迟、CoW Fork、WarmPool 就绪度、E2B 卷挂载、密钥、Panel 会话、桌面启动、事件、Webhook 及出站拦截指标。请参阅[API 概览](/zh/reference/api-overview/)。
- **Controller 透明出站联动与 CSI `VolumeSnapshot` CoW Fork 模式（`#89`）。** 在 `cubepod-controller` 中打通 `TransparentEgress`（`CUBEPOD_TRANSPARENT=1` + `NET_ADMIN`）与 WarmPool 出站密钥生命周期；新增 `--fork-mode=snapshot` 与 `--volume-snapshot-class` 支持基于 `snapshot.storage.k8s.io/v1` `VolumeSnapshot` 进行 CoW 克隆（与 `pvc-clone` 并行支持）；并补充控制器侧 Fork 与 WarmPool Prometheus 指标。
- **多副本 Secrets HA 与严格单沙箱 mTLS 置换（`#90`）。** 新增 `KubeSecretBackend`（`secrets.backend: "k8s"`），将 AES-256-GCM 加密后的 E2B 密钥持久化至 Kubernetes Secret 以支持无状态多副本 Gateway 高可用；新增 HA Vault 自动重加载（`Sync`）；并在 `/internal/v1/egress/exchange`（`--egress-mtls-addr`）上强制执行单沙箱严格 mTLS 校验。
- **Gateway 并发锁、统一特性开关与异步回收事件（`#91`）。** 引入按沙箱粒度的操作锁（`lockSandboxOp`）、防 TOCTOU 竞态的 `SyncPodBoxesOnce` 对账、空闲自动回收（Reaper）异步生命周期事件与 Webhook 投递、Gateway 与 Controller 统一的 `--feature-gate` 参数解析以及 E2B 卷挂载计数指标。
- **桌面会话可选 WebRTC 传输与 noVNC 优雅回退（`#95`）。** 在 `/sandboxes/{id}/desktop/start`（`images/desktop/cubepod-desktop-ctl` 与 `pkg/gateway/desktop.go`）新增 `transport: "webrtc" | "novnc"` 支持，返回 `webrtcUrl`、`transportUsed` 与 `fallbackReason`，在缺少 WebRTC 依赖时自动回退至 noVNC。请参阅[桌面环境与签名 Panel 代理](/zh/concepts/desktop-and-panel-proxy/)。
- **Python 与 TypeScript 原生 SDK 功能对齐（`#95`）。** 在 [Python SDK](/zh/sdks/python/) 与 [TypeScript SDK](/zh/sdks/typescript/) 中同步新增沙箱指标、只写 Secrets（`Secret.fill` / `fill_secret`）、持久化 E2B Volumes 内容读写、生命周期事件与签名 Webhook 以及桌面 `transport` 参数。
- **v0.6.0 Helm Chart 全量接线与 Gateway PDB（`#95`）。** 新增 `pdb.yaml`（当 `gateway.replicaCount > 1` 时默认自动开启 `PodDisruptionBudget`）、`secrets-key-secret.yaml` 与 `secrets.*` 后端配置、`egress.transparent`、`featureGates.*` 统一 `--feature-gate` 注入，以及配置 `e2bVolumes.rwxStorageClassName` 后自动激活 RWX `e2bVolumes` 与 `K8sE2BVolumeMounts`。请参阅[Kubernetes 与 Helm 部署指南](/zh/deployment/kubernetes-helm/)。
- **TypeScript E2B 兼容测试集、实时 K8s E2E 与文档完善（`#93`、`#94`、`#88`）。** 新增 TypeScript E2B 兼容测试套件 `test/e2b-compat-ts`（`make test-e2b-compat-ts`）、扩展 Python 兼容用例、新增实时 Kubernetes 集群 E2E 测试（`test/k8s-e2e/k8s_e2e_test.go`）、更新中英文站文档与 CEP 元数据、刷新 `og-banner.png` 分享图，并将 `docs/architecture.md` 翻译为英文同时保留 `docs/architecture_zh.md`。

## 问题修复

- **Controller、Vault 与 Gateway 边界并发加固（`#89`、`#90`、`#91`、`#92`）。** 加固 WarmPool 出站密钥同步、`VolumeSnapshot` 命名校验与构建密钥清理（`#89`）；修复 Vault 密钥置换/轮换竞态、复合 Fork Key 及 `Store.Sync` 锁顺序（`#90`）；消除 `SyncPodBoxesOnce` TOCTOU 误驱逐问题（`#91`）；强化指标租户隔离、限制 Prometheus 标签基数、清理已删除沙箱的环形缓冲区并加固 CPU/loadavg 采集边界（`#92`）。

## 升级前注意事项

`0.6.0` 相比 `0.5.4` 无 Kubernetes CRD Schema 字段变更。如从 `v0.5.0` 或更早版本升级，请务必在执行 `helm upgrade` **之前**应用最新 CRD：

```bash
kubectl apply -f deploy/helm/cubepod/crds/
```

升级前请核对 [Kubernetes 与 Helm 部署指南](/zh/deployment/kubernetes-helm/) 中的 `0.6.0` 默认配置变化：
- `secrets.backend` 默认为 `"k8s"`（多副本 HA 部署时需通过 `secrets.existingSecret`、`secrets.encryptionKey` 或 `gateway.secretsKeySecret` 配置共享 32 字节加密密钥）。
- `egress.transparent` 与 `featureGates.transparentEgress` 默认均为 `true`，两者同时开启时才启用透明 `nftables`/DNS 拦截。
- 设置非空的 `e2bVolumes.rwxStorageClassName` 现在会自动启用 `e2bVolumes` 与 `K8sE2BVolumeMounts`。

请将 `cubepod-controller`、`cubepod-gateway`、`cubepod-egress` 与 `cubepod-podd` 镜像及 `0.6.0` Helm Chart 同步升级，并更新客户端 SDK（`pip install -U cubepod==0.6.0` / `npm install cubepod@0.6.0`）。
